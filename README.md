# NoteBase (Python)

Markdown ノートアプリ。C# WinForms 版を Python 3.12+ / Tkinter / 標準ライブラリのみへ移植したもの。

---

## 起動

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
$env:PYTHONPATH = "."
python -m notebase
```

データは既定で `<repo>/MemoRoot/` 配下に保存。場所を変えたい場合:

```powershell
python -m notebase --memo-root C:\path\to\my\notes
# あるいは
$env:NOTEBASE_ROOT = "C:\path\to\my\notes"
python -m notebase
```

旧 C# 版が `NoteBase_csharp/bin/Debug/MemoRoot/` に残っている環境では初回起動時に自動コピーされます (現リポジトリは C# 版削除済み)。

## ノート種別

| 種別 | 用途 |
|---|---|
| 備忘録 (memo) | 普通のメモ |
| 手順書 (procedure) | 再利用可能な手順テンプレート |
| Todo (todo) | 行ごとに `- [ ]` でタスクを並べる。`@2026-05-10` で期限、`#tag` でタグ |
| ルーティーン (routine) | 周期チェックリスト。schedule (daily/weekly/monthly) に従い本日プラン候補に挙がる |
| チェックリスト (checklist) | 手順書同様のテンプレート (作業ごとに実施記録を残したい場合) |
| ログ (log) | 実施記録 (テンプレートからは自動的にこの type で作られる) |
| 日次メモ (daily) | 「本日のプラン」で自動生成。手動でも可 |
| プロジェクト (project) | プロジェクト概要 |

## 基本操作 (メイン画面)

| 操作 | UI / キー |
|---|---|
| ノート選択 | 左ペインの一覧をクリック |
| 検索 | ツールバーの検索欄 (タイトル・タグの部分一致) |
| 新規作成 | 「新規 (Ctrl+N)」 → 種別を選択 → 編集ウィンドウで保存 |
| 編集 | 「編集 (Ctrl+E)」 / 一覧をダブルクリック |
| 戻る | 「◀ 戻る」 / Alt+← (Wiki リンク遷移後の navigation) |
| 実施を開始 | (procedure / checklist 選択時) テンプレートから実施記録を作成 |
| 本日のプラン | チェックリスト + タイムボックス併記の `daily` ノートを生成 |
| ゴミ箱へ | 選択中ノートを `trash/` に移動 (復元可能) |

## 編集ウィンドウ

- タイトル / 種別 / ステータス / タグ / プロジェクト / 期限 をフォームで編集
- 本文は Markdown エディタ (Consolas 等幅、折り返し無し)

| キー / UI | 動作 |
|---|---|
| Ctrl+S | 保存 |
| Ctrl+V | クリップボードに画像があれば PNG として `images/` 配下に保存し `![](images/...)` を挿入。なければ通常テキスト貼付 |
| Ctrl+L | ノートピッカーを開いて他ノートのブロックを選択 → `[[Title#anchor]]` を挿入 |
| Explorer からドラッグ&ドロップ | 画像ファイルを取り込み |
| 「画像を追加…」 | ファイルダイアログから画像を取り込み (DnD のフォールバック) |
| 「キャンセル」 | (新規時) ドラフトをゴミ箱へ移動して終了 |

## リッチ Markdown 機能

### Wiki リンク

| 記法 | 意味 |
|---|---|
| `[[Title]]` | 別ノートへのリンク |
| `[[Title#見出し]]` | 別ノートの見出しへ |
| `[[Title\|alias]]` | エイリアス表示 |
| `[[Title#^abc123]]` | ブロック ID 指定 |
| `[[#見出し]]` | 同一ノート内アンカー |

未解決のタイトルは赤字で `[[Unknown]]` として表示。

### ブロック ID

行末に `^abc` を付けると、その行/段落にアンカーを付与:

```markdown
重要事項を整理 ^summary

- TODO: 後で確認 ^check1
```

ノートピッカー (Ctrl+L) で他ノートのブロックを選んだとき、未割当ならアプリが自動で 6 桁ランダム ID を生成・付与します。

### 行内メタ記法 (todo タスク)

```markdown
- [ ] レビュー @2026-05-10 #high
```

`@YYYY-MM-DD` は期限、`#tag` はタグ (現状 `@date` のみ「本日のプラン」候補抽出に使用)。

### ホバープレビュー

プレビュー上のリンクに **マウスを 500ms 載せる** と小ポップアップで遷移先のセクションが見えます。100ms 離れると消えます。Windows のタスクバーや画面端を考慮して位置を調整。

## プレビューの対話操作

### チェックボックスのトグル

プレビュー上の `☐` / `☑` を **クリック** すると、ソース Markdown の `- [ ]` ↔ `- [x]` が反転して保存されます。

### 階層化 (インデント)

```markdown
- [ ] 親タスク
  - [ ] 子タスク 1
  - [ ] 子タスク 2
    - [ ] 孫タスク
```

2 スペース (またはタブ 1 つ) = 1 レベル。プレビューで段階インデント表示 (タスク・通常リスト・番号付きリスト共通)。

### タイムボックス (Canvas 編集)

タイムボックス書式 `- HH:MM–HH:MM ラベル (Nm)` の連続行は **対話的な Canvas** に変換されます:

| 操作 | 効果 |
|---|---|
| タスクの **下端をドラッグ** | 5 分刻みでリサイズ |
| タスクの **中央をドラッグ** | 並べ替え (オレンジ線がドロップ位置を示す) |
| タスクを **ダブルクリック** | 詳細編集ダイアログ (詳細 / 実績分 / 遅延理由) |
| ドラッグ後にリリース | Markdown へ自動保存、時刻チェーン再計算 |

矩形の高さは所要分に比例 (1 分 = 2 px)。

### タスク詳細 (事前計画 + 事後の振り返り)

各タスクをダブルクリックするとダイアログが開き、以下を編集できます:

| 区分 | 項目 | 用途 |
|---|---|---|
| 計画 (事前) | ラベル / 計画分 / **詳細** | 「何をするか」の前提・サブ手順を残す |
| 実績 (事後) | **実績分** / **遅延理由** | 振り返り用。計画と差が出たときの背景を記録 |

ダイアログで保存すると Markdown には親行直下にインデントされた子行として書き出されます:

```markdown
- 09:00–09:15 朝のルーティン (15m)
  - 詳細: ストレッチとコーヒー
  - 実績: 25m
  - 遅延理由: 寝坊した
```

子行は値が入っている項目だけ書き出されます (空欄ならその行は出ない)。

Canvas 上の表示:
- `(15m → 25m)` の形で計画 → 実績の対比をヘッダ右に表示
- 計画より長引いた矩形は **朱色枠** に変わる
- `📝 詳細` / `⚠ 遅延理由` がラベル下に小さく表示

## 手順書 / チェックリストのテンプレート利用

1. 手順書 (`type=procedure`) またはチェックリスト (`type=checklist`) でテンプレートを作成
2. 一覧でテンプレートを選択 → ツールバー「**実施を開始**」が有効化
3. クリックで実施記録 (`type=log`、`instance_of=テンプレ ID`) のドラフトが作られ、編集ウィンドウが開く
4. 本文先頭に `> テンプレート: [[元タイトル]]` が自動挿入されているので、そこからテンプレに戻れる
5. 実施記録のチェック状態は独立 (テンプレ側は変わらない)
6. 過去の実施記録は `type=log` として一覧に残る

## 本日のプラン (チェックリスト + タイムボクシング)

1. ツールバーの「**本日のプラン…**」をクリック
2. ダイアログで:
   - 対象日 (既定: 今日) と開始時刻 (既定: 09:00)
   - **自動候補**: 今日該当のルーティーン + 期限が今日以前の未完了 todo タスク
   - 各行の **✓ 列をクリック** で取捨選択、**所要分をダブルクリック** で編集
   - 「ノートから追加…」「手動で追加…」で項目追加
3. 「作成」で `type=daily` ノートが保存され:
   - `## チェックリスト` (`- [ ]` リスト)
   - `## タイムボックス` (Canvas で対話編集可能)

完成したプランは普通のノートと同じ扱いで検索・編集・Wiki リンクが効きます。

## データ構造

```
MemoRoot/
├─ notes/<id>/             ← 1 ノート 1 フォルダ
│   ├─ index.md            ← 本文 (純粋 Markdown)
│   ├─ meta.json           ← メタデータ
│   └─ images/             ← 添付画像
├─ trash/<stamp>_<id>/     ← 削除ノート (移動のみ、復元可能)
├─ outputs/, indexes/, ... ← 将来用
```

`meta.json` は人間可読 JSON、本文は普通の Markdown ファイルなのでアプリ無しでも読み書き可能です。`images/` 内の画像はノート相対パス `images/xxx.png` で参照されるので、`MemoRoot` ごとコピーすれば別環境でもそのまま開けます。

## 制約

- Windows 専用機能 (クリップボード画像取得、OLE DnD) は Win32 API を `ctypes` で直接叩く実装。非 Windows では DnD/画像貼付は no-op になり、その他の機能は動く。
- プレビューの画像表示は **PNG / GIF のみ**。Tk PhotoImage の制約で JPEG/BMP は `[image: <name>]` プレースホルダで代替 (ファイル自体は保持される)。
- クリップボード画像は **24bpp BI_RGB / 32bpp BI_RGB / 32bpp BI_BITFIELDS (BITMAPV5HEADER)** に対応。8bpp 以下のパレット形式や RLE 圧縮は未対応。
- 行内メタ記法は `@YYYY-MM-DD` のみ抽出 (`#tag` は将来)。

詳細仕様は [docs/requirements-v2.md](docs/requirements-v2.md) 参照。
